# 평가 프레임 결과 (#116)

[English](eval_results.md)

11/24까지 받은 평가 프레임 전체(안개 48장, 야간 30장, 비 30장)를 원본·고정·적응형 보정으로 처음 돌린 결과입니다.
여기에는 숫자만 둡니다. 프레임, 라벨, 크롭, 번호판 문자, 발표용 이미지는 git 밖에 둡니다.
VLM 점수와 터널·역광 프레임은 아직 오지 않았습니다.

## 설정

| | |
| --- | --- |
| 안개 | 직접 찍은 블랙박스 클립 11개에 합성 안개를 넣은 48장([dashcam_results.ko.md](dashcam_results.ko.md)) |
| 야간 | AI Hub 71588, 장면 5개 × 6장 = 30장. h1gyeon9가 팀 공통 기준으로 고름 |
| 비 | AI Hub 630, 구간 5개 × 6장 = 30장(낮 4개, 밤 1개). leojuho가 같은 기준으로 고름 |
| 고정 보정 | 모든 프레임에 h1gyeon9의 기준값: Gaussian 3×3 σ 1.0, 감마 0.75, 히스토그램 평활화 없음, Unsharp 0.8. 이번 실행 전에 고정 |
| 적응형 보정 | `develop`의 leojuho 규칙(`src/adaptive/`)과 `apply_ops` |
| 번호판 라벨 | 안개만: 읽을 수 있는 번호판 13개(C의 라벨). AI Hub에는 번호판 문자가 없어 번호판 지표는 안개만 계산 |
| 차량 라벨 | 안개: 222대(C의 라벨). 야간·비: AI Hub 박스를 `tools/aihub_vehicles.py`로 변환([#90](aihub_vehicles.ko.md)). 야간은 24장에 114대이고, 차량이 무리로 묶인 6장은 뺌. 비는 30장에 82대 |
| 시간 | 고정과 적응형 보정을 108장 모두 한 PC(C의 PC)에서 다시 돌림. 다시 만든 프레임이 평가한 프레임과 바이트까지 같아서 시간만 바뀜 |

```bash
python tools/eval_lists.py --list data/manifests/a_night/evaluation_frames.csv low_light --list data/annotations/rain_eval_runs.csv rain
python tools/plate_report.py --scenes data/annotations/scenes.json data/annotations/aihub_vehicles.json
python tools/env_report.py --scenes data/annotations/scenes.json data/annotations/aihub_vehicles.json --envs data/annotations/envs.csv
```

`rain_eval_runs.csv`는 leojuho의 비 목록(`source`, `frame`)에 비 `frames.csv`의 구간 이름을 `scene`으로
붙인 것입니다. 이렇게 하면 구간별 VLM 점수를 조건별로 나눌 수 있습니다.

## 실행 전 확인

- 받은 프레임: 야간 고정 보정과 야간·비 적응형 보정은 C가 `develop`의 `fixed_enhance`, `adaptive_enhance`로
  다시 만든 결과와 픽셀까지 같습니다. 적응형 설정도 60장 모두 다시 돌린 결과와 같습니다.
- 안개: OCR과 차량 수치가 11/20 실행([#78](dashcam_results.ko.md))과 모두 같고, 시간만 다릅니다.

## 알 수 있는 것

1. **야간과 비에서는 보정해도 차량 검출이 거의 바뀌지 않습니다.** 고정과 적응형 보정이 바꾸는 차량은 1–4대이고,
   의미 있는 차이는 없습니다.
2. **고정 보정은 이번에도 안개 번호판을 나쁘게 합니다**(문자 정확도 0.81 → 0.70). #78과 같습니다.
3. **야간에서 적응형 보정은 모든 프레임에 발동하고, 차량을 3대 덜 찾습니다.** 프레임이 매우 어둡습니다(밝기 중앙값 8).
   고정 보정에 비해 4대를 놓치고 1대를 더 찾습니다(p 0.38). 방향 정도로만 봐야 합니다.
4. **비는 검출기에 어렵습니다.** YOLO가 라벨 차량의 0.10을 찾고, 200 px 이상 차량도 0.15만 찾습니다. 비 튜닝용 구간
   2개(평가 프레임 아님)에서 확인해 보니 자기 차 걸러내기가 박스를 하나도 지우지 않았고, 라벨도 차량과 잘 맞았습니다
   (IoU 0.7–0.95). 그러니 매칭 문제가 아니라 검출기가 이 차량들을 놓치는 것입니다.
5. **야간과 비에서는 어느 조건에서도 번호판을 읽지 못했습니다.**

## 주의할 점

- 표본이 작습니다. 안개의 읽을 수 있는 번호판은 13개이고, 야간과 비의 차이는 차량 1–4대입니다.
- 번호판 지표는 안개만 있습니다. 야간과 비는 차량 라벨만 있고 번호판 문자가 없습니다.
- 안개 차량 라벨은 맑은 날 프레임에서 YOLO로 만든 것이라, 안개 검출률은 그 기준에 대한 비율입니다. 야간과 비의 라벨은
  AI Hub의 것입니다.
- 설정은 이번 실행 전에 고정했습니다. 이 결과를 보고 설정을 바꾸지 않습니다.
- VLM 칸은 callmeaein의 `score.csv`가 올 때까지 비어 있습니다. 오면 `plate_report.py --skip-ocr`와
  `env_report.py`를 OCR 없이 다시 돌립니다. 터널·역광은 프레임이 생기면 추가합니다.
- 시간은 한 PC에서 한 번 잰 값이고, 벤치마크가 아닙니다.
