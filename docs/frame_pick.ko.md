# 평가 타임스탬프 고르기 (ALL-01)

[English](frame_pick.md)

맑은 날 클립의 어느 프레임을 평가에 넣을까요? `tools/pick_frames.py`는 안개를 입히기 전에 앞 차량의
크기로 고릅니다. 번호판 탐색이나 OCR 결과는 보지 않으므로, 파이프라인이 이미 잘 읽는 프레임으로
치우치지 않습니다(#77).

## 규칙

| 단계 | 규칙 | 이유 |
| --- | --- | --- |
| 스캔 | 500 ms마다 YOLO 차량 박스. 클래스와 임계값은 파이프라인과 같음(`detect_vehicles`) | 파이프라인이 보는 차량과 같게 |
| 가까운 차량 | 가장 넓은 박스가 1920 px 기준 **280 px** 이상(프레임 폭에 비례) | 번호판(520 mm)은 차 폭(1.7–1.9 m)의 약 0.29라 약 80 px. OCR이 잘 읽는 크기([번호판 크기 확인](plate_size_check.ko.md)) |
| 세지 않음 | 왼쪽·오른쪽 화면 끝에 잘린 박스, **2.5:1**보다 넓은 박스 | 옆을 지나가는 차, 옆모습과 마주 오는 차. 2.4:1 정도까지의 비스듬한 뒷모습은 번호판이 보였음 |
| 촬영 차량 | YOLO가 차로 보는 대시보드는 `detect_vehicles`가 직접 뺌 | [번호판 인식](plate_recognition.ko.md#촬영-차량-78) 참고 |
| 프레임 | 넓은 것부터, **3초** 이상 간격, 최대 **5개**. 가장 넓은 박스가 이미 고른 것과 IoU **0.7** 이상 겹치면 건너뜀 | 같은 차의 이웃 프레임은 같은 번호판. 정체 때는 앞차가 몇 초씩 서 있음 |
| 구간 | 이런 프레임이 가장 많은 **20초** 구간, 같으면 폭 합이 큰 쪽, 그다음 이른 쪽 | 안개 클립은 10–30초 |

타임스탬프는 안개 클립 기준 시간으로 적고, 프레임을 추출하면(가장 가까운 프레임, `src.io.video.extract_frames`와 같음)
스캔한 바로 그 프레임이 나옵니다.

## 작업 순서

```bash
# 1. 차량 박스, data/clear/day_01.vehicles.json에 저장(박스만, 이미지 없음)
python tools/pick_frames.py scan data/clear/day_01.mp4
# 2. 구간과 타임스탬프. data/manifests/member_c.csv에 행을 추가하고 make 명령을 출력
python tools/pick_frames.py pick data/clear/day_01.mp4 --clip fog_01.mp4 --density medium
# 3. 그 구간의 안개 클립
python tools/synth_fog.py make data/clear/day_01.mp4 data/clips/fog_01.mp4 --start-ms 12000 --end-ms 32000 --density medium --horizon 0.54
```

그다음은 [합성 안개 작업 순서](synthetic_fog.ko.md#작업-순서)의 3단계부터 이어 갑니다. 매니페스트를 합치고,
프레임을 추출하고, 맑은 기준 프레임을 저장하고, 라벨 초안을 만듭니다.

| 옵션 | 기본값 | |
| --- | --- | --- |
| `--step-ms` (scan) | 500 | 샘플 간격 |
| `--clip` | – | 안개 클립 이름, 예: `fog_01.mp4` |
| `--density` | – | `light`, `medium`, `heavy`. 결과를 보기 전에 정함([농도](synthetic_fog.ko.md#농도)) |
| `--length-ms` | 20000 | 구간 길이 |
| `--gap-ms` | 3000 | 두 프레임 사이 최소 시간 |
| `--max-frames` | 5 | 클립당 프레임 수 |
| `--min-width` | 280 | 1920 폭 기준 차량 박스 폭(px) |
| `--manifest` | `data/manifests/member_c.csv` | 행을 추가함. 이미 있는 클립은 거부 |

`pick`은 다른 파일로 만든 스캔(SHA-256이 다름)을 거부합니다. 스캔은 CPU에서 1080p 영상 1분에 약 10초 걸립니다.

## 직접 찍은 클립에서 본 것 (11/19)

전방 카메라 클립 11개, 각 1분, 1920×1080, 30.3fps, 11/17과 11/18의 흐린 낮.

- **촬영 차량의 대시보드를 "차"로 봅니다.** 11개 클립 중 6개에서 YOLO가 화면 폭의 0.84–0.99이고 블랙박스
  글자 띠 바로 위인 1055–1066행에서 끝나는 박스를 찾았습니다(샘플 프레임 53장). 모두 대시보드였습니다.
  가장 넓은 박스라 그대로였다면 골랐을 것이고, 번호판 후보도 그 안에서 찾았습니다. 클립 2개에서는 대시보드에 비친
  차도 찾았습니다(821–837행에서 시작하는 박스 11개). 이제 `detect_vehicles`가 둘 다 뺍니다.
- **파일에 적힌 것보다 프레임이 적습니다.** 루프 녹화 파일의 처음 0.96초(29프레임)는 디코딩되지 않고,
  나머지는 끊김이 없습니다. `scan`은 디코딩된 프레임 수를 세므로 구간이 그 너머로 가지 않습니다. 프레임
  시간은 어디서나 같은 만큼 밀리므로 안개 클립, 그 프레임, 맑은 기준 프레임은 서로 맞습니다.
- **번호판이 작습니다.** 광각 렌즈라 폭 280 px인 차는 불과 몇 미터 앞에 있습니다. 샘플 프레임 1,313장 중
  521장에 그런 차가 있었고, 한 클립(정체)에서는 같은 차가 대부분이라 같은 장면 규칙으로 2장만 남았습니다.
- 결과: 구간 11개에서 타임스탬프 48개, 클립당 2–5개.
