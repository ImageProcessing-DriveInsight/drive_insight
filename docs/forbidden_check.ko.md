# A-12: 금지 OpenCV·stub 검사 (#67)

제출 대상 `src/`의 입출력 외 OpenCV 사용과 `_stub` 식별자를 정적 검사한다.
검사 대상 코드를 import하거나 실행하지 않으며 Python 표준 라이브러리만 사용한다.

## 실행

저장소에서 다음 명령을 실행한다.

```bash
python tools/check_forbidden.py src/
python tools/check_forbidden.py src/ --json
python -m tools.check_forbidden src/
```

경로를 생략하면 저장소의 `src/`를 검사한다. 상대 입력 경로는 실행 디렉터리가 아닌
검사기가 있는 **저장소 루트** 기준이다. 절대 경로도 허용하며 여러 파일·폴더를
지정할 수 있다. 디렉터리 아래 `*.py`를 재귀 검사하고 중복 파일은 한 번 검사한다.
테스트의 OpenCV 비교 코드나 도구까지 검사하려면 해당 경로를 명시해야 한다.
기본 제출 검사는 `tests/`, `tools/`, 가상환경을 포함하지 않는다.

일반 출력은 `파일:줄:열: 코드: 설명`과 검사 파일 수·발견 건수를 표시한다.
JSON 출력은 `files_scanned`, `files`, `findings`, `exit_code`를 담는다.
각 finding은 `path`, `line`, `column`, `code`, `message`를 담는다.
줄·열은 1부터 시작하며 AST가 보고한 열은 UTF-8 바이트 오프셋 기준이다.
동일 위치·종류·설명은 중복 제거하지만, 금지 함수를 import하고 사용하면
import와 사용 위치가 각각 보고될 수 있다. 발견 건수는 고유 함수 개수가 아니다.

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 모든 대상 분석 완료, 발견 사항 없음 |
| 1 | 금지 OpenCV 또는 stub 발견 |
| 2 | 경로·읽기·구문 오류 등으로 검사 불완전; 위반도 있으면 2 우선 |

없는 경로, Python 파일이 없는 폴더, 읽을 수 없는 파일, 잘못된 인코딩·문법을
정상 통과로 처리하지 않는다. 인코딩은 Python의 BOM·coding cookie 규칙을 따른다.
심볼릭 링크 루트·파일은 지원하지 않는다. CLI 인자 오류도 argparse의 종료 코드 2다.

## 이번에 정한 검사 정책

- AST로 `cv2` import 별칭, `from cv2 import ...`, 단순 변수 별칭을 추적한다.
  직접 호출뿐 아니라 함수 참조·콜백 대입도 보고한다. `getattr(cv2, ...)`도 확인한다.
- 입출력 허용 목록은 `imread`, `imwrite`, `imdecode`, `imencode`, `imreadmulti`,
  `imwritemulti`, `imcount`, `VideoCapture`, `VideoWriter`, `VideoWriter_fourcc`다.
  현재 팀 코드가 사용하는 영상·이미지 입출력을 허용하고 새로운 항목은 검토 후
  `ALLOWED_CV2_IO`와 테스트를 함께 수정한다. `resize`, `cvtColor`, 각종 필터는 금지다.
- `CAP_PROP_FPS`, `IMREAD_COLOR` 같은 대문자 상수 참조는 허용한다.
  대문자 이름도 함수로 호출하면 허용하지 않는다. 허용한 Capture/Writer 객체의
  `read`, `get`, `write`, `release` 등 메서드에 대한 객체 타입 추론은 하지 않는다.
- `from cv2 import *`와 상수 문자열로 확인되는 동적 cv2 import는 별도 위반으로
  보고한다. 명시적 import로 바꾸어 검토 가능하게 한다.
- `_stub`는 Python NAME 토큰에 포함되면 보고한다. 함수·클래스·인자·변수·속성을
  포함한다. 주석, docstring, 일반 문자열은 제외한다. 예외적으로
  `getattr(obj, 'enhance_stub')` 같은 명시적 동적 속성 문자열은 보고한다.
  따라서 단순 문자열 grep과 결과가 다르다.

이 정책은 기능 명세의 검사 요구를 구현하며, 허용 함수 목록·오류 코드·문자열 제외는
이번 구현에서 정한 운영 기준이다. 검사 통과가 모든 동적 실행 경로의 무위반을 증명하지는 않는다.

## 정적 분석의 한계와 후속 점검

별칭 분석은 실행 순서를 완전히 모사하지 않는 보수적 분석이다. 같은 스코프에서 cv2
별칭을 다른 객체로 재할당하면 오탐할 수 있다. 일반 함수 인자와 중첩 함수의 로컬
별칭은 구분하지만, 임의의 `eval`/`exec`, 컨테이너에 숨긴 함수, 외부 모듈 재수출,
계산된 import 문자열, 복잡한 `global`/`nonlocal`·컴프리헨션 스코프는 완전 추적하지 않는다.
동적 우회가 필요하면 명시적 코드로 바꾸고 코드 리뷰로 확인한다.

새 코드 병합 후 제출용 `src/`에서 다시 실행한다. 테스트는 현재 `src/`의 무위반도
확인하므로 전체 pytest 실행에도 제출 검사 회귀가 포함된다. 실제 평가 영상의 화질·OCR·
성능 검증과는 별개이며 그 결과를 이 검사로 대체하지 않는다.
